# AgentDeck 0.1.207

Working with an outside developer is now a first-class flow. Invitations are sent by email — the invitee signs in to AgentDeck Remote with that address and the invitation is waiting right after login, with a real invitation email (and a push notification if they already use AgentDeck). Links and QR codes are gone from the guest flow. On the desktop, a dedicated Developers screen (bottom of the sidebar, badged only when something new arrives) shows each guest across four pages — live status with pending permission requests, an activity timeline, a chat styled like a session chat with file attachments, and session sharing. Guest chat now arrives on the desktop in real time, shows image previews instead of identical file icons, and no longer duplicates your own messages. Owners can also see and chat with connected guests from the phone app, while guests themselves never see the owner's usage statistics or account limits — the server refuses those calls for every guest role.

This release also fixes a family of guest-connection failures found in live testing: the relay room mismatch that kept guest and host from ever meeting, a guest acceptance that could take over the browser paired with your own PC, and the missing way back to your own PC from guest mode.

Media tools grew up as well. Settings → Media now covers image, speech-to-text, text-to-speech, video, and embeddings, each with a searchable model picker that lists only models the provider actually offers for that capability. OpenRouter is supported end to end, including image generation, and generated images are saved as session artifacts. The assistant only uses these tools when you explicitly ask — verified with a 26-scenario live suite so that anything the base model can do itself (SVG, HTML, code, diagrams) never silently spends your media API credits.

Updater behavior is cleaner: if several releases shipped while you waited, installing now takes you straight to the latest one instead of stepping through each, and the web app no longer shows false update banners when you switch between PCs.

## Highlights

- **Email-based developer invitations** — invite by email, accept by signing in; real invitation emails; push notification for existing users; invitation appears immediately after login with no waiting screen.
- **Developers screen (desktop)** — status / activity / chat / sessions per guest; pending permission requests answerable inline; session sharing front and center; new-activity badge instead of a permanent count.
- **Developers tab (phone)** — owners see connected guests and chat with them from the PWA; permission changes stay on the PC.
- **Guest privacy boundary** — guests can never read the owner's usage, cost, or account-limit data, nor other guests' conversations; enforced server-side per role.
- **Guest connection fixes** — relay room unification, paired-browser takeover prevention, "back to my PC" from guest mode, guest bar no longer covering the workspace.
- **Media capabilities** — five capability slots with provider-filtered model pickers; OpenRouter image generation; artifacts from generated media; explicit-request-only tool policy.
- **Updater** — installs only the newest version; no false update banners on PC switch; failed preparations unlock retry.
- **Quality** — narrow-window chat header and composer no longer overlap; splash screens show the real product marks; opening a folder that no longer exists reports an error instead of failing silently.
