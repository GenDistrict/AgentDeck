# AgentDeck 0.1.196

AgentDeck 0.1.196 makes the first minutes and the daily reconnects noticeably smoother — the phone app now paints your last-known home instantly while it reconnects, new users who stall during CLI sign-in get concrete help on screen, and guests now see only the sessions you invited them to. It also fixes the desktop guest-invite button and makes every file in the Files panel open or download the way you expect.

## Highlights

### Reconnects that feel instant

- **The web app opens on your last-known home immediately** — sessions and accounts render from a local per-PC cache while the live connection is established in parallel, WhatsApp-style. Nothing is stored on any server; the cache lives only on your phone and is wiped when a guest session ends or a device is unpaired.
- **The relay socket now opens while approval is still pending**, shaving seconds off restricted-network connections.
- **Multiple PCs, honest states.** If the PC you last used is offline, the web app says so and offers your other PCs right there — no more retry loops against a machine that is asleep. The PC switcher highlights exactly the machine you tapped.
- A rare start-up crash in the web app ("Could not open the screen") was fixed at the root, and the error screen now offers switching PCs as an escape hatch.

### A first run that helps when it matters

- **Stuck sign-in guidance.** If a Claude or GPT CLI sign-in has not completed after 30 seconds, the card shows an engine-specific checklist (is the terminal window still open? did the browser link get clicked? is the subscription active?). After a while it adds the one line most people need: retry is usually fastest. Both retry paths reset cleanly.
- **A clear moment of success.** The instant an account connects, a banner above the start box says you are ready, and the cursor lands in the input so the first message is one keystroke away.

### Guests see only what you invited them to

- **Session scoping.** A guest connected through an invite now sees only the sessions started by them or explicitly shared with them — not every session running on your PC. Owners can share or unshare a session from the guest activity view at any time.
- **Per-device model caps.** A paired device or guest can be limited to a lighter model — useful for demos and outside developers.
- **Invite links can open the app directly** on phones that have it installed.

### Files behave like files

- **Desktop Files panel: click opens with the OS default application** — exactly like double-clicking in Explorer/Finder, with a confirmation step for executable types. Editing text files (like `.env`) moved to an explicit Edit button, and binary or oversized files now offer "open with default app" instead of a dead-end warning.
- **Web app: files can be downloaded to the phone** when the device has file permissions — every download passes four permission gates (file access, transfer permission, workspace boundary, per-device folder policy) and is audited.
- **Folder links written by the agent now work.** "[Open the folder](file:///…)" used to render as dead text; the desktop now reveals the location in Explorer/Finder, and the phone shows the path so you can find it on the PC.

### Fixes worth knowing

- **Desktop guest invites work again** — creating an invite link from Settings → Connected devices failed with "Service request is not allowed" on some installations. The whole invite lifecycle (create, list, approve, extend, revoke) is now verified end-to-end against production in the release pipeline.
- The preview channel is now a truly separate app — installing a preview never touches your stable AgentDeck, its data, or its running sessions, and both can run side by side.
- Saving diagnostics no longer fails silently when the Documents folder is unavailable (it falls back to Downloads, and failures are shown on screen).
- Connection privacy wording was rewritten in plain language across all nine display languages.
- Repeated sign-in drop detection on the home screen now triggers reliably.

### Under the hood: every button, really clicked

Every release is now gated by an automated pass that boots the packaged app twice (fresh and existing user) and **physically clicks every visible button, toggle and select** — plus a per-screen click sweep of the web app — failing the release on any crash or dead control. This pass caught two of the fixes above before they could ship.
