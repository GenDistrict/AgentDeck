# thread0 0.1.215

thread0 0.1.215 makes account changes, PC pairing, and external-developer access behave as one coherent system. A browser that signs out and into another account no longer inherits the previous account's PC or trust state. A PC that was already approved reconnects without asking for a new safety code, while a new device identity still requires explicit approval.

This release also removes the remaining legacy pairing steps from email-based developer invitations. An invited developer enters through the verified email grant, the owner is notified when the developer actually connects, and revoking the grant immediately stops local and relay access. Stale invitation cards are removed after reconciliation, and the guest sees a specific access-ended explanation with an appropriate way out even when they do not own a PC.

Email onboarding now gives clear feedback on the first submit, uses current thread0 branding in verification mail, actively notices verification on the desktop, and offers the next device-connection action. Chat dictation uses the recognizer built into the current device and paints partial speech live without requiring a separately configured media-transcription provider.

## Highlights

- **Account-scoped Remote state** — PC selection, trusted keys, discovery, and active transports are isolated by the exact signed-in account. Signing out cancels the old connection before another account starts.
- **Approved PCs stay approved** — selecting the same PC again starts a fresh connection attempt, but an unchanged approved device id and public key reconnect without a new six-digit code. A new or changed key still requires approval.
- **No bootstrap dead ends** — a missing server user record is bootstrapped and retried once, and service-connection failures offer both retry and sign-in with another account.
- **A single pairing code** — PC confirmation uses the selected-PC card as the only source of the safety code; the PC list is the only PC selector. The desktop setup view keeps its QR, balanced guidance, and a usable full-width address.
- **Email-native developer access** — verified email grants no longer enter the personal-device pairing flow. The obsolete mail-draft action is gone, and the owner gets a deduplicated notification when the guest actually joins.
- **Revocation that finishes** — removing a developer closes the relay immediately, persists server cleanup for retry, removes stale invitation entries, and explains to the guest that the owner ended access.
- **Reliable email verification** — the confirmation dialog appears on the first account-creation attempt, verification mail says thread0, and the desktop actively detects completion and guides the user toward connecting a device.
- **Built-in live dictation** — desktop and mobile chat microphones use device speech recognition, show partial words as they arrive, and remain independent of configurable media transcription.
- **Cleaner Remote identity** — the simplified thread0 Remote icon is included across PWA icon sizes, maskable assets, and favicons.
- **Localized recovery copy** — pairing and technical connection failures use the nine-language catalog instead of leaking hardcoded Korean or internal error strings.

## Reliability and regression coverage

The release gate now carries a permanent regression ledger: every user-visible bug fixed here records its reproduction, expected result, fixed version, and mandatory automated tests. This release passed the complete regression suite (199 test files), packaged new/existing-user boot checks (12/12), phone/tablet/desktop layout checks, packaged interaction sweeps, live Claude/Codex/routine turns, the full first-user journey, signed-artifact verification, and post-publication checks for both desktop channels and all Remote URLs.

At the release owner's direction, physical-device-only checks were explicitly waived for this release. They are recorded as waived rather than reported as passing; automated browser, packaged-app, live-service, signing, notarization, and publication checks still ran.
