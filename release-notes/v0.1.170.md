# AgentDeck 0.1.170 — First Public Release

AgentDeck 0.1.170 is the first public stable release of AgentDeck: one secure workspace for Claude, Codex, local models, cloud model APIs, and company-managed AI.

It brings multiple agent accounts, native harness workflows, local privacy and security controls, encrypted access from other devices, usage visibility, and controlled automation into one desktop application.

## Highlights

### Claude and Codex in one workspace

- Connect multiple Claude subscription and ChatGPT/Codex accounts on one computer with isolated authentication and configuration.
- Use Claude Code and Codex through one interface while retaining streaming, tools, approval requests, models, and reasoning controls.
- Continue work with another account when a quota is reached, or hand work between Claude and Codex with a recent-context summary.
- Preserve session drafts, attachments, workspace context, and approval state while supervising concurrent sessions.

### Local, cloud, and company-managed AI

- Run local GGUF models with the embedded llama.cpp runtime.
- Connect Ollama and LM Studio/OpenAI-compatible local servers.
- Use supported Google Vertex AI, Amazon Bedrock, Microsoft Azure AI Foundry, and OpenRouter paths.
- Connect organization-approved compatible gateways and AI deployed inside a corporate network through signed policy and allowlisted routes.

### Privacy and agent security

- AgentDeck does not centrally store prompts, responses, tool output, work-file contents, local paths, or provider credentials.
- Personal-data and sensitive-context masking can pseudonymize selected information locally before a request is sent and restore it locally in the response (Beta).
- Prompt-injection protection checks external content for instruction overrides, impersonation, secret-exfiltration attempts, approval bypasses, hidden actions, and dangerous commands before model exposure (Beta).
- Account credentials and configuration directories are isolated.
- Per-turn permissions and approval cards keep consequential actions visible; irreversible actions retain a human checkpoint.

Content sent to a selected model provider remains subject to that provider's data, retention, and training policies. Users and organizations must configure any required provider-side storage or training opt-out themselves.

### Secure access from other devices

- Pair a phone, tablet, or another computer with explicit desktop approval and a matching safety code.
- Protect session traffic with end-to-end encryption, pinned device identity, and fresh ephemeral session keys.
- Prefer direct WebRTC connectivity with an opaque encrypted relay fallback when a direct connection is unavailable.
- Limit and revoke remote capabilities per paired device.

### Usage and controlled automation

- View subscription limits, token usage, cache usage, and estimated metered API cost in one place.
- Learn from repeated local approval patterns to reduce routine prompts while retaining confirmation for high-impact actions (Beta).
- Prevent the computer from sleeping while agents are running or waiting for approval.
- Keep automatic-review denials and errors visible in chronological tool records without flooding or displacing the conversation.

## First-release stabilization

- Added a visible reset control whenever desktop zoom differs from 100%, so accidental zoom changes are easy to recover.
- Prevented routine successful automatic-review notices from flooding the transcript.
- Kept automatic-review denials and errors at their original chronological position.
- Improved concurrent availability of the local automatic-review classifier.
